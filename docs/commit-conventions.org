#+title: Commit conventions
#+author: Frestein

* Purpose

This document is the single source of truth for commit messages in this
repository. It defines the message format, the canonical scope names, and
the historical spellings that are no longer used. History is not rewritten;
this document only describes new commits.

* Message format

#+begin_src text
type(scope): description
type: description
#+end_src

- Types in use: =chore=, =feat=, =fix=, =refactor=, =style=, =docs=, =perf=.
- A scope is optional: use =type: description= for changes that do not belong
  to a specific component.
- When present, a scope is a single component name without a slash: =emacs=,
  =nvim=, =qutebrowser=, =chezmoi=, =hyprland=, =fish=, =yazi=.
- The subsystem may go into the description as an optional =section:= prefix:
  - =feat(emacs): lua: add lsp config=
  - =chore(emacs): lang/lua: enable +fennel flag=
  - =chore(nvim): util/chezmoi: drop extra=
- Omit the prefix when the scope already names the subsystem.
- If a change touches several components, use one primary scope, omit the
  scope, or split the change into separate commits. Do not combine scopes.
- The description is lowercase and has no trailing period.
- Separate the subject from the body with a blank line.
- Keep the subject within 50 characters when possible; 72 is the hard limit.
- Wrap the body at 72 characters. This is enforced by the =check-commit-body=
  hook; a line that is only a URL may exceed the limit.
- Wrap code identifiers in backticks in the subject. Example:
  =fix(systemd): check-disk-usage: use `OnCalendar` instead of `OnUnitActiveSec`=
- In the body, backticks are optional and serve only as visual separation
  between code and prose.

* Canonical scopes

| Canonical       | Deprecated aliases      | Why                                                     |
|-----------------+-------------------------+---------------------------------------------------------|
| =emacs=           | =doom=, =doom/*=            | The =doom= scope is no longer used                        |
| =nvim=            | =nvim/*=                  | Subsystems move into the description                    |
| =qutebrowser=     | =qb=, =qute=, =qutebrowser/*= | Full project name is unambiguous                        |
| =hyprland=        | =hypr=, =hypr/*=            | Full compositor name; =hypr= is only the config directory |
| =chezmoi=         | =cz=, =ch=, =chezmoi/*=       | Short abbreviations were early experiments              |
| =chezmoi-watcher= | =cz/watcher=              | A separate component, not a chezmoi subsystem           |

Every other top-level scope found in the history is canonical as written.

#+name: scope-list
#+begin_src emacs-lisp :results raw :exports none
(let ((file (or buffer-file-name
                (error "Tangle this block from the Org file"))))
  (with-temp-buffer
    (insert-file-contents file)
    (goto-char (point-min))
    (re-search-forward "^#\\+name: canonical-scopes$")
    (re-search-forward "^#\\+begin_src")
    (let ((start (point))
          scopes)
      (re-search-forward "^#\\+end_src")
      (save-restriction
        (narrow-to-region start (match-beginning 0))
        (goto-char (point-min))
        (while (re-search-forward "\"\\([^\"]+\\)\"" nil t)
          (push (match-string 1) scopes)))
      (mapconcat #'identity (nreverse scopes) ","))))
#+end_src

stages = ["commit-msg"]

* Rules

1. Use only canonical scopes from =canonical-scopes=. Add a new scope there
   before using it; never introduce an alias for an existing one.
2. If a change belongs to a component but no canonical scope fits, ask the user
   whether to add one and propose concrete names.
3. When a component with a canonical scope is removed, ask the user whether to
   remove its scope, then remove it from the =canonical-scopes= block and
   regenerate the hook configuration.
4. Do not rewrite published history. Amending your own most recent,
   unpublished commit is fine.

* Tooling

The =canonical-scopes= block and the local =check-commit-body= hook are tangled
into =prek.toml= in the repository root. Regenerate it whenever either changes.
The =commit-msg= hooks are installed with =prek install=; update remote hook
versions with =prek update=. The local hook runs
=scripts/check-commit-body.py=, which skips the subject and exempts URL-only
lines from the width limit. This Org file is =linguist-detectable= and
=prek.toml= is =linguist-generated=; keep both attributes when adding literate
sources.
